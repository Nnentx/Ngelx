# Build548: user device feedback after Build547

Base: Build547 source commit 7b8de740f3779eaa8967deb4523869a28bcdb487, verified run 39459395807. Preserve its existing generated source and signing identity.

- Generic Create gallery opens image/video selection and infers selected content type. Explicit photo/video tools keep their original modes and multi-photo selection. Picker/camera actions reject reentry, wait for draft recovery and ignore immediate returning taps. Physical touchscreen issues are not diagnosable from a screenshot.
- Private call name/photo comes from the other signed-in chat member, both caller and recipient, rather than shared callTitle. Group presentation and session ownership UID stay intact. Peer listener is disposed on close. Speaker active appearance is white; inactive is dark, and the button reads the audio manager preference with a serialized toggle.
- Chat image thumbnails use intrinsic image aspect ratio under smaller width/height bounds, with no extra dark padded rectangle. Original image bytes and full-screen zoom are preserved.
- Guest panel offers explicit audio/video choices and a private camera-only preview. Preview camera is disposed before LiveKit publishing. No guest media is published without an explicit local join choice. Both compact and expanded controls propagate that choice. Host approval, authorization checks, mute/kick behavior, immediate local media stop and reconnect guards remain.
- Guest sees their own video/audio tile. One to three guests appear at the right, above the comments. Four or more guests use a bounded grid with the host, video for camera users and avatar for audio users; profile names, local Sen label, mic status, speaking border and host moderation remain visible. No duplicate overlay rails or stale ready box.
- Free virtual gifts are enabled through the existing comment-event transaction, without balances, coin purchases, charges or cash value. Catalog/quantity limits, active-stream/ban check, retry IDs and duplicate-send lock are retained. UI clearly labels gifts as free. No database security rule or production-service deployment is part of this change.

Validation before CI: seven source/lifecycle regression tests, idempotent transformation against the exact Build547 assembled artifact. Added Flutter tests for both caller/recipient identity selection, image bounds/aspect ratio, guest-grid thresholds and gift catalog/quantity validation. Full analysis, Android signing and phone acceptance follow CI.

Device acceptance: photo and video from generic gallery; repeated picker taps/cancel; both call directions and minimize/restore; white speaker outputs loudspeaker, dark selects earpiece (also test headphones); tall screenshot has no outer dark rectangle; host invitation accepted in audio/video modes, preview stays private, local preview visible after joining, mic/camera/leave controls; 1/3/4/8 guests with mixed video and audio, keyboard and comments; free gift reaches both viewers once, duplicate retry is not counted twice, send after live end rejected.

- Publication success notice closes after two seconds even when action-bearing snackbars have accessibility timeout suppression. Its action dismisses before switching to the feed; owned timer is cancelled on close, replacement and dispose, so it cannot dismiss a later notice. Verify with accessibility navigation enabled and ordinary mode, plus Akışa git and tab navigation.
